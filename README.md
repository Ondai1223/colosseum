# マギアリーナ(旧コロッセウム)公開用リポジトリ
url: https://github.com/Ondai1223/colosseum.git

**ゲームジャンル**
3vs3のコマンドバトル

**メインシステム：** 魔素システム
キャラクターの攻撃などによって、属性がフィールド上のマス目に付与される。
同じマス目の中に付与された属性が2つ存在するとHPダメージやデバフなどの戦闘に有利な効果が発動される。
この属性の組み合わせによって、従来の『攻撃』と『防御』の駆け引きとは別に『属性』の駆け引きが生まれ、戦略性が生まれる

**私の役割:** クライアントエンジニア、サブリーダー</br>
**使用技術:** Unreal Engine 5, C++, Git/GitHub</br>
**開発期間:** 2025年9月〜現在 (7ヶ月以上継続中)</br>

### 2. 開発時の課題への対応と学習

| 項目 | 詳細 |
| :--- | :--- |
| **技術的課題** | Unreal Engineのガベージコレクションへの対応。メンバー変数に登録した配列の参照が失われ、配列内の要素がGCによって意図せず解放されてしまう事象に遭遇しました。 |
| **解決策** | 当該の配列を保持するメンバー変数にUPROPERTY()マクロを付与し、GCの追跡対象に登録することで、参照が維持され、意図しない解放を防ぎました。 |
| **成長過程** | C++の**ポインタの概念**や**Unreal Engineの命名規則**など、学ぶことが多々ありましたが、この挑戦を通じて**ゲームの核となる機能を実装できる**レベルまで成長しました。 |

| 項目 | 詳細 |
| :--- | :--- |
| **技術的課題** | レベル遷移時に一瞬デフォルトの背景（空）が見える現象、およびロード画面終了時のアニメーション演出がスキップされる問題。 |
| **解決策** | C++側で bAutoCompleteWhenLoadingCompletes = false に設定し、自動終了を抑制。BP側の BeginPlay でローディング用ウィジェットを Add to Viewport してから ローディング用のCloseAnimationを再生することで、シームレスな遷移を実現。 |
| **成長過程** | エンジン機能（MoviePlayer）に頼り切るのではなく、自作ロジックとバトンタッチさせることで、ユーザー体験を損なわない高品質な遷移演出を構築できるようになった。 |

### 3. チームでの貢献と成長姿勢

このプロジェクトを通じて、**実践に近い形**でチーム開発を行うことができ、**現場で働くイメージ**を持つことができました。
* **プロの基準に合わせた主体的学習:**
当初はUnreal Engine 5やGitの経験が浅かったものの、「公式ドキュメントやソースコードを調査し、自分なりの考察を持ってから質問する」というプロのエンジニアが求めるコミュニケーションを徹底しました。その結果、プロのメンターから効率的に技術を吸収でき、参画から短期間でゲームのコアロジック（魔素システム）の設計・実装を任されるまでに成長しました。

* **コードを読むことを通じた設計力の向上:**
初期タスク（BattleAction.cpp 等）では、シニアプログラマーが書いた既存コードを徹底的に読み解き、設計の意図や命名規則、メモリ管理の作法を基盤として開発フローを習得しました。この経験が、後のストラテジーパターンやポリモーフィズムを用いた拡張性の高い設計へと繋がりました。

* **技術的なブリッジとプロジェクトの推進力（サブリーダー）:**
20名規模の多職種混合チームにおいて、プログラマーの枠を超えたサブリーダーとして活動しました。具体的には、デザイナーが作成したアセットが正しくゲームに反映されるようディレクションを行い、他セクションで発生したGit/GitHubのエラー解消など、チーム全体の開発が止まらないための技術的サポートをしました。また、リーダーと共にゲーム性の見直しや残タスクの管理、広報にも携わりました。
* **主体的な学習:** 当初はUEやGitの知識が不足していましたが、「**調べてから考察を含めて質問する**」ことを徹底。プロのフィードバックを効率的に吸収し、短期間でコアロジックを任されるまでに成長しました。
* **初期タスク:** キャラクターの攻撃アクションの実装（`BattleActoin.cpp`など）を通じて、**先輩プログラマーのコードを基盤**に開発フローを習得。プロのコードを読むことで、設計のお手本をイメージできるようになりました。
