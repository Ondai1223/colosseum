UEでテンプレートを使用せず、一から通信をするには面倒だったので覚書を共有します。
あと通信の挙動についても記しておきます。


まず、UEの基本的なクラスでそれぞれ役割が最初っから割り当てられているので、まずはそれを。
一応調べればすぐに出てきます。

--------------------------------------------------------------------------------
・GameMode(GameModeBase) クラス
　ライフサイクル：レベルが存在する間
　レプリケーション：サーバーのみに存在し、クライアントでは存在しない
　用途：プレーヤーのスポーン、勝敗判定、ルール管理など


・GameState クラス
　ライフサイクル：サーバーに一つつくられ、各クライアントにレプリケートされる
　レプリケーション：サーバーで一つ作られクライアントにレプリケートされる
　用途：ゲームの進行状況、プレーヤーリスト保持

・PlayerState
　ライフサイクル：サーバーとすべてのクライアントに生成され、すべての環境にレプリケートされる
　レプリケーション：サーバーとすべてのクライアントに作成され、すべての環境にレプリケートされる
　用途：プレーヤーのスコア、選択キャラ、名前などのプレーヤー情報

・PlayerController クラス
　ライフサイクル：各プレーヤーに一つ（接続時に生成される）
　レプリケーション：サーバー、クライアントにそれぞれ存在。サーバーにはすべてのクライアントのものがレプリケートされる
　用途：入力処理、UI操作、カメラ制御

レプリケートの設定

プロパティの設定は以下のようにします。
以下のプロパティが有効なのは、PlayerState、PlayerController、GameStateクラス

UPROPERTY(Replicated)
	int Test = 0;

送られてきたタイミングにコールバックを挟みたい場合は
UPROPERTY(Replicated , ReplicatedUsing = OnRep_Test)
	int Test = 0;

このプロパティは宣言したあとインスタンスに認識させる必要があります。

下記は、ARoleSelectPlayerState クラスでユニット配置のPlayerState です。
以下の仮想関数の中で次のように宣言します。






void ARoleSelectPlayerState::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);

    DOREPLIFETIME(ThisClass, Test);		//<--こんな感じで認識させます。(ThisClassは自分のクラスをマクロ化したものなのでコンパイル時にARoleSelectPlayerStateに置き換わります。)
}





コールバック関数は以下のようになります。
void ARoleSelectPlayerState::OnRep_Test(
							 int Old		//<-前回の数値
		 )
{
    UE_LOG(LogTemp, Log, TEXT("OnRep_Test():%s:%d -> %d"), (HasAuthority() ? TEXT("サーバー") : TEXT("クライアント")), Old, Test);
}


このコールバックの注意点は、Test に書き込まれたときに発生するのではなく、転送するタイミングで値が前回と同じじゃなければ発生しません。
違う値が書き込まれて、転送タイミング後に呼ばれます。
　なので、このコールバックが呼ばれたとき必ず、Test != Old になります。

なので、

 Test = 1;
 Test = 0;
 Test = 1;

とコードを書くと
転送タイミングでは Testの値が 1 なで、コールバックが呼ばれません。
